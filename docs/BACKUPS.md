## Если существующей рабочей копии нет или она непригодна

Выполнять следующие действия только из доверенной среды с уже разрешённым доступом к внешнему адресу PostgreSQL Render. Получить строку подключения через защищённый канал; не отправлять её в чат, GitHub, историю команд или логи. Инструмент читает её из переменной процесса **BACKUP_DATABASE_URL**. Не добавлять новые сетевые секреты в настройки этой среды в качестве обхода текущего блокера.

Для локального клиента нужны Python 3, pg_dump и pg_restore, совместимые с версией рабочей PostgreSQL. Опционально можно использовать существующий локальный контейнер как клиент через `--client-container <имя>`. При этом секрет передаётся через окружение Docker exec, не аргументом командной строки. Доверять этому Docker daemon так же, как машине с ключами.

```sh
python scripts/postgres-backup.py dump --output-dir /secure/backups/velora
```

Каталог должен находиться вне checkout и иметь права 700; новые файлы создаются с правами 600. Скрипт:

- допускает только внешний PostgreSQL-хост *.render.com, режим TLS verify-full; при проблеме доверия останавливается;
- использует read-only PGOPTIONS и pg_dump, не изменяет строки/схему источника, ограничивает ожидание блокировок;
- создаёт custom-format dump, каталог объектов и manifest с SHA-256, размером, версией клиента и временем UTC;
- не печатает пароль/URL и не передаёт их аргументами клиента;
- оставляет неудачную выгрузку как .partial, не выдаёт её за готовую копию;
- не удаляет предыдущие копии и не выполняет автоматическую ротацию.

Если URL содержит sslmode=require/disable, инструмент откажется. Настроить доверенную цепочку и verify-full; не отключать TLS-проверку. Если используется sslrootcert вместе с клиентом в контейнере, сертификат должен быть доступен по этому пути внутри контейнера. Версия pg_dump не может быть старше версии сервера: при несовместимости выбрать подходящий проверенный клиент, не обходить ошибку.

Выгрузка читает всю БД и может создавать нагрузку/расход исходящего трафика; сначала определить размер и допустимое окно. Скрипт не создаёт платные ресурсы. Содержимое дампа включает персональные данные и password hashes, поэтому требуются защищённое хранение и ограниченный доступ.

## Проверка восстановления без рабочей базы

Для custom dump, созданного инструментом и имеющего manifest:

```sh
python scripts/postgres-backup.py verify-local /secure/backups/velora/ИМЯ.dump
```

Нужен локальный Docker с заранее доступным проверенным образом PostgreSQL 17, закреплённым по digest в скрипте. Этот вариант проверен только с PostgreSQL 17; версия рабочей Render пока неизвестна. Для другой версии необходимо сначала подобрать соответствующий закреплённый образ и протестировать его отдельно.

У команды восстановления **нет параметра адреса целевой БД**: она всегда создаёт новый локальный контейнер, без сети и опубликованных портов. Проверяет checksum, восстанавливает dump с --exit-on-error, проверяет таблицу users/столбцы и считает записи без вывода содержимого. Записывает отдельный verified.json. В finally останавливает контейнер; не удаляет его или том. При несовпадении checksum восстановление не начинается. Не добавлять дампы и отчёты с данными в GitHub.

Это проверка фактической загрузки дампа, а не гарантия целостности всех бизнес-данных. Для копии рабочей БД дополнительно согласовать сверку количества записей/балансов в рамках одного снимка, необходимые роли/расширения и требования к восстановлению приложения. Стандартный pg_dump не включает cluster-wide роли; --no-owner/--no-privileges предназначены для переносимой проверки, права рабочего приложения нужно проверить отдельно.

## Что остаётся для запуска

1. Из доступной авторизованной панели Render установить идентичность рабочей БД, версию, размер, тариф, наличие копий/PITR, время последней успешной копии и срок хранения. Это сейчас внешний блокер.
2. Если копии нет — создать её безопасным методом выше в согласованное окно. Если уже есть — проверить именно её поддерживаемым способом на отдельной базе, без перезаписи источника.
3. Подтвердить результат восстановления. Сохранить защищённую независимую копию вне исходной БД и этой cloud-сессии; отдельно определить шифрование, срок хранения, расписание и проверку свежести. Локальный файл с checksum этого не заменяет.
4. После этого представить конкретный коммит Velora AI и получить подтверждение развёртывания. До подтверждения не сливать ветку и не деплоить. Реальная платная генерация остаётся выключенной.

Дамп не является PITR и не доказывает наличие настроенных автоматических резервных копий Render. Автоматическое расписание или независимое хранилище в этой работе не включались.
