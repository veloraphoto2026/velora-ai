# Velora AI

ИИ-фотостудия: регистрация, вход, личный кабинет и две бесплатные генерации на аккаунт.

## Локальная разработка

Node.js 24, npm и PostgreSQL 17. Установить зависимости: `npm ci`.
Скопировать `.env.example` в `.env`, указать параметры локальной PostgreSQL и приватный случайный `JWT_SECRET`. Можно создать ключ через Node crypto и сохранить его непосредственно в защищённый локальный файл; не добавлять `.env` в Git.
Запуск: `npm start`. Сервер начинает слушать порт только после успешной инициализации БД. Без `JWT_SECRET` запуск завершается ошибкой. `DATABASE_URL`, если задан, используется вместо стандартных параметров PG*. Проверка TLS не отключается приложением.

При запуске создаётся таблица users, если её нет, и устанавливается DEFAULT 2 для новых аккаунтов. Существующие записи и балансы не сбрасываются. Новые таблицы имеют ограничение неотрицательного баланса. Запуск на рабочей БД требует отдельного подтверждения.

Без токена провайдера регистрации, вход и личный кабинет работают; генерация возвращает 503 без списания. Сетевые секреты среды и Render API для локальной разработки не нужны. Для реальной генерации приложение использует существующую интеграцию Replicate, но настройка и вызовы провайдера в этой работе не выполнялись.

## Проверки без платных запросов

Создать **новую локальную тестовую БД** с именем `velora_accounts_test_<суффикс>`, затем:

```sh
createdb -h 127.0.0.1 -U velora velora_accounts_test_local
TEST_DATABASE_URL=postgresql://velora@127.0.0.1:5432/velora_accounts_test_local npm test
```

Тесты отклоняют внешние адреса и имена БД без тестового префикса. Используется настоящая PostgreSQL и локальный имитатор генератора, без сетевых запросов к ИИ. Проверяются регистрация, нормализация email, параллельные дубликаты, вход, профиль, недействительные JWT, ошибки генератора, отсутствие настройки провайдера, параллельное списание и исчерпание двух попыток. DOM-тест через jsdom выполняет регистрацию, вход, выход, отправку фото, обновление баланса и восстановление сессии. Это не визуальная проверка браузера.

Тестовые аккаунты сохраняются с уникальными адресами example.invalid: тесты не удаляют данные. БД Render не используется.

## Учёт генераций

`POST /api/generate` требует JWT. `VELORA_TEST_KEY` больше не даёт обход авторизации и баланса. PostgreSQL блокирует строку пользователя на время генерации: из трёх одновременных запросов с балансом 2 только два вызывают генератор. Баланс уменьшается после успешного ответа; обычная ошибка провайдера или некорректный результат откатывают транзакцию. Повторная инициализация, вход и обновление страницы не восстанавливают потраченные попытки.

Две попытки выдаются на аккаунт, а не на подтверждённого человека. Подтверждение email и защита от массовой регистрации пока отсутствуют. Прерывание процесса или сети после выполнения задания провайдером не обеспечивает строго однократное выполнение: для такого режима нужен устойчивый журнал заданий и идемпотентность. Долгая генерация удерживает соединение и блокировку аккаунта; для большой нагрузки потребуется очередь.

## Перед запуском на сайте

1. Проверить и подтвердить изменения перед отправкой ветки/слиянием и развёртыванием.
2. Проверить резервное копирование рабочей PostgreSQL; локальная копия разработки его не заменяет.
3. Проверить параметры подключения и постоянный JWT_SECRET в целевом приложении, не меняя текущие данные/балансы.
4. Отдельно подтвердить настройку и контрольный платный вызов провайдера генерации.
5. Решить ограничения массовой регистрации/повторной отправки перед открытым запуском; после разрешённого развёртывания проверить сценарий на целевом HTTPS-домене.

## Результат локальной проверки 24 октября 2026

Пройдены интеграционные тесты на PostgreSQL 17 и DOM-тесты. Дополнительно в установленном Chromium проверены регистрация, две генерации с имитатором, исчерпание баланса, сохранение нулевого баланса после обновления/повторного входа и мобильная ширина 390 px. Внешние запросы браузера перехвачены; платных вызовов не было. Рабочая база Render не использовалась.
